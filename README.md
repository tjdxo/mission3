# Mini NPU Simulator

## 1. 실행 방법

### 실행 환경
- Python 3.8 이상
- 외부 라이브러리 사용 없음
- 표준 라이브러리 `json`, `time`만 사용

### 제출 파일
- `main.py`: 메인 실행 파일
- `README.md`: 실행 방법 + 결과 리포트
- `data.json`: 분석 대상 JSON 파일

### 실행 방법
터미널에서 아래 명령어를 실행합니다.

```bash
python main.py
```

프로그램 실행 후 아래 두 가지 모드 중 하나를 선택합니다.

1. **사용자 입력 (3x3)**
   - 3x3 필터 A 입력
   - 3x3 필터 B 입력
   - 3x3 패턴 입력
   - MAC 점수, 평균 연산 시간(ms), 판정 결과 출력

2. **data.json 분석**
   - `data.json`의 필터와 패턴을 로드
   - 각 케이스별 점수/판정/PASS-FAIL 출력
   - 크기별 성능 분석 결과 출력
   - 전체 테스트 요약 출력

### data.json 위치
- `main.py`와 같은 디렉토리에 `data.json` 파일이 있어야 합니다.
- 코드에서 `DATA_FILE = "data.json"`으로 고정되어 있으므로 파일명도 동일해야 합니다.

## 2. 구현 요약

### 2-1. 라벨 정규화 방식
프로그램 내부에서는 결과 라벨을 `Cross`, `X` 두 가지로만 통일해서 사용했습니다.

정규화 규칙은 다음과 같습니다.

- `+` → `Cross`
- `cross` → `Cross`
- `x` → `X`

이 정규화를 적용한 이유는 JSON 데이터의 입력 형식과 프로그램 내부 비교 기준을 일치시키기 위해서입니다.  
예를 들어 `expected` 값이 `+`로 들어오더라도 내부에서는 `Cross`로 바꿔서 비교하므로, 비교 로직이 단순하고 안정적으로 유지됩니다.

### 2-2. MAC 연산 구현 개요
MAC(Multiply-Accumulate) 연산은 같은 위치의 값을 서로 곱한 뒤, 그 결과를 모두 더하는 방식으로 구현했습니다.

예를 들어 `N x N` 패턴과 필터가 있을 때:

- `pattern[i][j] * filter[i][j]`
- 모든 위치에 대해 반복
- 누적합을 최종 점수로 사용

외부 라이브러리 없이 이중 반복문으로 직접 구현했습니다.

예시 구현 구조는 다음과 같습니다.

```python
def calculate_mac(matrix_a, matrix_b):
    score = 0.0
    size = len(matrix_a)

    for i in range(size):
        for j in range(size):
            score += matrix_a[i][j] * matrix_b[i][j]

    return score
```

### 2-3. 판정 방식
두 필터 점수를 비교해서 더 큰 쪽을 최종 판정으로 사용했습니다.

- Cross 점수 > X 점수 → `Cross`
- X 점수 > Cross 점수 → `X`
- 두 점수 차이가 매우 작으면 → `UNDECIDED`

### 2-4. 동점 처리 정책 (epsilon)
부동소수점 계산에서는 아주 미세한 오차가 발생할 수 있습니다.  
이 문제를 해결하기 위해 아래 기준을 사용했습니다.

```python
EPSILON = 1e-9
```

즉,

```python
abs(score_a - score_b) < 1e-9
```

이면 동점으로 보고 `UNDECIDED` 처리합니다.

이 정책을 사용하면 사람이 보기에는 같은 값인데 컴퓨터가 다르다고 오판정하는 문제를 줄일 수 있습니다.

### 2-5. 입력 및 검증 구조
코드는 다음 항목을 검증하도록 구성했습니다.

- `data.json` 루트가 dict인지
- `filters`가 dict인지
- `patterns`가 dict인지
- 필터 키가 `size_N` 형식인지
- 패턴 키가 `size_N_idx` 형식인지
- `input` 존재 여부
- `expected` 존재 여부
- 행렬이 비어 있지 않은 2차원 배열인지
- 정사각형 행렬인지
- 선언된 크기와 실제 행렬 크기가 일치하는지
- 모든 원소가 숫자인지 (`bool` 제외)

검증 실패 시 프로그램이 중단되지 않도록 하고, 해당 케이스만 FAIL 처리하도록 구성했습니다.

## 3. 결과 리포트

### 3-1. 전체 동작 흐름
JSON 분석 모드에서는 아래 순서로 동작합니다.

1. `data.json` 로드
2. 필터 검증 및 라벨 정규화
3. 패턴 검증 및 크기 추출
4. 해당 크기의 필터 선택
5. MAC 연산 수행
6. 점수 비교 후 결과 판정
7. expected와 비교하여 PASS/FAIL 판정
8. 크기별 성능 데이터 저장
9. 최종 요약 및 성능 표 출력

### 3-2. FAIL 케이스 원인 분석
현재 코드 기준에서 FAIL은 크게 두 경우로 발생합니다.

#### 1) 데이터 형식 오류
예를 들어 아래와 같은 경우입니다.

- 필터 키 형식 오류
- 패턴 키 형식 오류
- `input` 누락
- `expected` 누락
- 행렬 크기 불일치
- 숫자가 아닌 값 포함
- 해당 크기의 필터가 없음

이 경우는 코드가 예외 없이 처리하고, 해당 케이스를 FAIL로 기록합니다.

#### 2) 판정 결과와 expected 불일치
MAC 점수 계산 후 실제 판정 결과가 `expected`와 다르면 FAIL입니다.

예:
- 계산 결과는 `X`
- expected는 `Cross`
- 따라서 FAIL

#### 3) 동점 처리로 인한 FAIL 가능성
두 필터 점수가 사실상 같으면 `UNDECIDED`로 처리합니다.  
이 경우 expected는 `Cross` 또는 `X` 중 하나일 가능성이 높으므로 FAIL이 됩니다.

즉, FAIL은 반드시 코드 버그 때문이 아니라 다음 원인일 수 있습니다.

- 필터 가중치 설계 문제
- 데이터 자체의 애매한 패턴 구조
- 동점 처리 정책에 따른 정상적인 결과

### 3-3. 0 FAIL일 경우 해석
만약 실행 결과가 `0 FAIL`이라면, 그 이유는 다음과 같이 설명할 수 있습니다.

- 모든 JSON 구조가 검증 조건을 만족했다.
- 모든 패턴이 올바른 크기의 필터와 매칭되었다.
- 각 패턴의 MAC 점수가 expected 라벨과 일치했다.
- 동점(`UNDECIDED`)이 발생하지 않았거나 expected와 충돌하지 않았다.

즉, 0 FAIL은 “우연히 맞았다”기보다  
**검증 로직 + 정규화 로직 + MAC 판정 로직이 데이터와 일관되게 맞아떨어졌기 때문**이라고 볼 수 있습니다.

## 4. 성능 분석

### 4-1. 측정 방식
성능 측정은 `measure_mac_pair()` 함수에서 수행했습니다.

- 같은 입력에 대해 MAC 연산을 10회 반복
- `time.perf_counter()`로 측정
- ms 단위 평균 시간 계산
- I/O 시간은 제외하고 연산 함수 호출 구간만 측정

### 4-2. 성능 표 해석
출력 표의 각 열은 다음 의미를 가집니다.

- **크기**: 행렬 크기 (`3x3`, `5x5`, `13x13`, `25x25`)
- **평균 시간(ms)**: 같은 크기 패턴들에 대한 평균 처리 시간
- **연산 횟수(N²)**: 행렬 한 개에 대한 원소 방문 수

예를 들어:

- `3x3` → `9`
- `5x5` → `25`
- `13x13` → `169`
- `25x25` → `625`

행렬 크기가 커질수록 방문해야 하는 원소 개수가 증가하므로 평균 시간도 일반적으로 증가합니다.

### 4-3. 시간 복잡도 분석
MAC 연산은 `N x N` 행렬의 모든 원소를 한 번씩 방문합니다.  
따라서 한 번의 MAC 연산 시간 복잡도는 다음과 같습니다.

```text
O(N²)
```

코드 구조상 내부 반복문은 다음과 같습니다.

```python
for i in range(size):
    for j in range(size):
        score += matrix_a[i][j] * matrix_b[i][j]
```

바깥 반복이 `N`, 안쪽 반복도 `N`이므로 전체 반복 횟수는 `N × N = N²`입니다.

### 4-4. 연산 횟수와 측정 결과의 연결
프로그램은 패턴 하나를 판정할 때 아래 두 MAC을 계산합니다.

- pattern vs Cross filter
- pattern vs X filter

즉 내부적으로는 MAC 연산이 2번 실행됩니다.  
하지만 각 MAC 자체의 시간 복잡도는 여전히 `O(N²)`입니다.

따라서 전체 판정 비용도 상수배 차이만 있을 뿐, 복잡도는 그대로:

```text
O(N²)
```

로 볼 수 있습니다.

성능 표에서 작은 크기보다 큰 크기의 시간이 증가한다면,  
이는 단순히 데이터가 많아진 것이 아니라 **이중 반복문이 처리해야 할 원소 수 자체가 증가했기 때문**입니다.

### 4-5. 왜 NPU/GPU가 필요한가
이 프로그램은 CPU에서 순차적으로 MAC 연산을 수행합니다.  
행렬 크기가 커질수록 계산량이 빠르게 증가하므로 대규모 연산에서는 성능 한계가 생깁니다.

실제 AI 하드웨어에서는 이런 곱셈-누적 연산을 대량 병렬 처리하기 위해 GPU나 NPU를 사용합니다.  
이번 과제의 구현은 바로 그 기본 원리를 작은 규모에서 직접 시뮬레이션한 것입니다.

## 6. 결론

이번 프로그램은 작은 규모의 NPU 동작 원리를 Python으로 직접 구현한 시뮬레이터입니다.

핵심은 다음과 같습니다.

- 패턴과 필터의 유사도를 MAC 점수로 계산한다.
- 라벨 정규화로 입력 형식을 통일한다.
- 부동소수점 오차를 고려해 epsilon 기반 동점 처리 정책을 사용한다.
- JSON 데이터 검증을 통해 잘못된 입력도 안전하게 처리한다.
- MAC 연산은 `N²`에 비례하므로 입력 크기가 커질수록 성능 비용이 증가한다.

즉, 이 과제는 단순한 문자열 판별이 아니라  
**행렬 연산, 데이터 검증, 결과 비교, 성능 분석까지 포함한 Mini NPU 시뮬레이션 구현**이라고 정리할 수 있습니다.
