# Mini NPU Simulator

## 1. 프로젝트 소개

이 프로그램은 입력된 2차원 숫자 패턴이 `Cross(십자가)`에 가까운지, `X`에 가까운지를  
MAC(Multiply-Accumulate) 연산으로 판별하는 Python 콘솔 애플리케이션입니다.

사람은 모양을 보고 바로 구분할 수 있지만, 컴퓨터는 숫자만 다룰 수 있으므로  
패턴과 필터를 같은 위치끼리 곱해서 모두 더하는 방식으로 유사도를 계산합니다.

이 프로젝트는 다음 두 가지 모드를 제공합니다.

- **모드 1**: 사용자 입력 기반 3x3 패턴 판별
- **모드 2**: `data.json` 파일 기반 일괄 판별 및 성능 분석

## 3. 구현 요약

### 3-1. MAC 연산 구현
패턴과 필터의 같은 위치 원소를 곱하고 모두 더해서 점수를 계산합니다.

예를 들어 `(i, j)` 위치마다 아래 연산을 수행합니다.

```python
score += matrix_a[i][j] * matrix_b[i][j]
```

이 연산을 전체 `N x N` 영역에 대해 반복하여 최종 MAC 점수를 구합니다.

### 3-2. 점수 비교 방식
두 필터의 점수를 비교해서 더 큰 쪽을 최종 결과로 판정합니다.

- Cross 점수 > X 점수 → `Cross`
- X 점수 > Cross 점수 → `X`
- 두 점수 차이가 매우 작음 → `UNDECIDED`

### 3-3. 동점 처리 정책 (epsilon)
부동소수점 오차를 고려하기 위해 다음 기준을 사용했습니다.

```python
EPSILON = 1e-9
```

즉,

```python
abs(score_a - score_b) < 1e-9
```

이면 동점으로 보고 `UNDECIDED` 처리합니다.

이 정책은 미세한 실수 오차 때문에 결과가 잘못 뒤바뀌는 것을 막기 위한 것입니다.

### 3-4. 라벨 정규화 방식
프로그램 내부 표준 라벨은 다음 두 가지입니다.

- `Cross`
- `X`

입력값은 아래처럼 정규화합니다.

- `'+'` → `Cross`
- `'cross'` → `Cross`
- `'x'` → `X`

이렇게 정규화하면 JSON 내부 표기 방식이 달라도 비교는 일관되게 수행할 수 있습니다.

### 3-5. 사용자 입력 처리
모드 1에서는 3x3 행렬을 한 줄씩 공백으로 구분해서 입력받습니다.

최소한 아래 오류를 검사합니다.

- 각 줄의 숫자 개수가 3개가 아닌 경우
- 숫자로 변환할 수 없는 값이 포함된 경우

오류 발생 시 안내 문구를 출력하고 해당 줄을 다시 입력받도록 구성했습니다.

## 5. 결과 리포트

### 5-1. 전체 결과 요약
실행 결과 총 6개의 패턴을 분석했고, 그중

- **통과(PASS)**: 3개
- **실패(FAIL)**: 3개

로 확인되었습니다.

PASS 케이스:
- `size_5_2`
- `size_13_1`
- `size_25_2`

FAIL 케이스:
- `size_5_1`
- `size_13_2`
- `size_25_1`

### 5-2. FAIL 케이스 원인 분석
이번 실패 3건은 모두 공통적으로 **동점 처리 규칙** 때문에 발생했습니다.

#### 1) size_5_1
- Cross 점수: `0.9000`
- X 점수: `0.9000`
- 판정: `UNDECIDED`
- expected: `X`

두 점수가 동일해서 승자를 정할 수 없었고,  
정책상 `UNDECIDED`가 반환되었기 때문에 FAIL이 발생했습니다.

#### 2) size_13_2
- Cross 점수: `7.5000`
- X 점수: `7.5000`
- 판정: `UNDECIDED`
- expected: `Cross`

이 케이스도 동일하게 두 점수가 완전히 같았습니다.  
따라서 expected가 `Cross`여도 결과는 `UNDECIDED`가 되어 FAIL입니다.

#### 3) size_25_1
- Cross 점수: `4.9000`
- X 점수: `4.9000`
- 판정: `UNDECIDED`
- expected: `X`

이 경우도 마찬가지로 점수가 동일하여 판정 불가가 되었고,  
기대값이 `X`였기 때문에 FAIL 처리되었습니다.

### 5-3. 실패 원인의 해석
이 3개의 실패는 **코드 계산 오류 때문이 아니라 데이터와 비교 정책의 결과**라고 볼 수 있습니다.

즉,

1. 프로그램은 MAC 연산을 정상 수행했다.
2. 두 점수가 같으면 epsilon 기준에 따라 `UNDECIDED` 처리했다.
3. expected는 `Cross` 또는 `X`였기 때문에 결과적으로 FAIL이 되었다.

따라서 실패 원인은 다음처럼 정리할 수 있습니다.

- **로직 문제**: 아님
- **수치 비교 문제**: 있음 (동점 처리 정책 적용)
- **데이터/필터 설계 문제**: 있음 (두 필터가 동일 점수를 만들 수 있음)

### 5-4. 라벨 정규화가 중요한 이유
JSON 데이터에서는 `expected`가 `+` 또는 `x`로 들어올 수 있고,  
필터 키도 `cross`, `x`처럼 소문자 형태일 수 있습니다.

이 값을 그대로 비교하면 다음 문제가 생길 수 있습니다.

- `'+'` 와 `'Cross'`는 의미는 같지만 문자열은 다름
- `'x'` 와 `'X'`도 대소문자 차이로 불일치 가능

따라서 내부에서 모두 `Cross`, `X`로 통일해 비교하면  
불필요한 FAIL을 줄일 수 있습니다.

### 5-5. 부동소수점 비교 정책이 필요한 이유
실수 계산에서는 사람이 보기엔 같아도 내부 값은 약간 다를 수 있습니다.

예를 들어:

- `0.9000000000000000`
- `0.8999999999999999`

이런 경우 단순 `==` 비교를 사용하면 의도와 다른 판정이 나올 수 있습니다.  
그래서 `abs(a - b) < 1e-9` 같은 epsilon 기준이 필요합니다.

이번 과제에서는 이 기준을 사용해 거의 같은 값을 동점으로 처리했습니다.

## 6. 성능 분석

### 6-1. 측정 방식
성능 측정은 MAC 연산을 **10회 반복 실행**한 뒤 평균 시간을 구하는 방식으로 수행했습니다.

- 시간 측정 함수: `time.perf_counter()`
- 단위: ms
- 측정 구간: MAC 연산 함수 호출 중심

### 6-2. 실제 측정 결과

| 크기 | 평균 시간(ms) | 연산 횟수(N²) |
|------|----------------|---------------|
| 3x3  | 0.001842 | 9 |
| 5x5  | 0.005404 | 25 |
| 13x13 | 0.020170 | 169 |
| 25x25 | 0.067237 | 625 |

### 6-3. 성능 표 해석
행렬 크기가 커질수록 평균 시간이 증가하는 것을 확인할 수 있습니다.

- `3x3`는 원소 수가 적어서 매우 빠름
- `5x5`는 `3x3`보다 처리할 값이 많아서 시간이 증가
- `13x13`, `25x25`에서는 증가 폭이 더 커짐

이는 MAC 연산이 행렬 전체 원소를 직접 순회하기 때문입니다.

### 6-4. 시간 복잡도 분석
핵심 MAC 함수는 다음 구조입니다.

```python
for i in range(size):
    for j in range(size):
        score += matrix_a[i][j] * matrix_b[i][j]
```

바깥 반복문이 `N`, 안쪽 반복문도 `N`번 실행되므로  
총 반복 횟수는 `N x N = N²`입니다.

따라서 시간 복잡도는 다음과 같습니다.

```text
O(N²)
```

### 6-5. 연산 횟수와 측정 결과의 연결
성능 표의 `연산 횟수(N²)`는 각 행렬 크기에서 한 번의 MAC 계산에 필요한 기본 연산량을 의미합니다.

- `3x3` → `9`
- `5x5` → `25`
- `13x13` → `169`
- `25x25` → `625`

실제 평균 시간도 이 숫자가 커질수록 함께 증가했습니다.  
즉, 단순히 "큰 입력이라 느려졌다"가 아니라  
**이중 반복문이 처리해야 하는 원소 수가 N²로 늘어나기 때문에 시간이 증가했다**고 설명할 수 있습니다.

### 6-6. 왜 CPU보다 NPU가 유리한가
이 프로젝트는 CPU에서 순차적으로 MAC 연산을 수행합니다.  
하지만 실제 AI 모델은 훨씬 더 큰 행렬과 더 많은 필터를 사용합니다.

이 경우 `N²` 연산이 매우 많이 반복되므로  
CPU만으로는 속도 한계가 생길 수 있습니다.

그래서 실제 AI 하드웨어에서는 많은 MAC 연산을 병렬로 처리할 수 있는  
GPU나 NPU가 사용됩니다.

## 7. 결론

이번 프로젝트를 통해 다음 내용을 직접 구현하고 확인할 수 있었습니다.

- MAC 연산은 같은 위치의 값을 곱해서 모두 더하는 방식이다.
- 패턴과 필터의 유사도는 MAC 점수로 계산할 수 있다.
- 라벨 정규화는 입력 형식을 통일해서 비교 오류를 줄이는 데 중요하다.
- 실수 비교에서는 epsilon 기반 동점 처리 정책이 필요하다.
- 행렬 크기가 커질수록 연산량은 `O(N²)`로 증가한다.
- 실제 실행 결과에서도 크기가 커질수록 평균 시간 증가가 확인되었다.
- FAIL 케이스는 코드 버그가 아니라 동점 판정 정책 때문에 발생할 수 있다.

즉, 이 프로그램은 단순한 패턴 비교기가 아니라  
**행렬 연산, 라벨 정규화, 동점 처리, 성능 측정, 실패 원인 분석**까지 포함한  
작은 NPU 시뮬레이터라고 정리할 수 있습니다.
